02 · Nuestra propuesta

Un solo ESP32 cumple tres funciones.

1

Recibe

Recibe mensajes de una notebook u otros ESP32 mediante Wi-Fi.

2

Guarda

Almacena registros en SQLite, dentro de su memoria flash.

3

Responde

Devuelve los datos cuando otro dispositivo los solicita.

La misma placa actúa como servidor web y servidor de datos.

03 · El hardware

¿Qué es un ESP32?

Es un microcontrolador: una pequeña computadora programable que puede conectarse por Wi-Fi y controlar dispositivos electrónicos.

ProcesadorWi-FiMemoria flashEntradas y salidas

En este proyecto usamos como referencia un ESP32-S3.

04 · Base de datos

¿Qué es SQLite?

Es un motor de base de datos relacional pequeño que organiza información en tablas y permite consultarla usando SQL.

Como una planilla organizada

idsensorvalue
1temperature24.7
2humidity55.0
3pressure1012.3

La diferencia clave

SQLite no necesita un servidor de base de datos independiente.

El programa abre un archivo iot.db y realiza consultas directamente sobre él.

Un archivo · Muchas filas

05 · El almacenamiento

¿Dónde viven los datos?

ESP32-S3placa física
Flashmemoria persistente
SPIFFSsistema de archivos
iot.dbarchivo SQLite

SQLite

Sabe crear tablas, insertar, consultar y borrar registros.

SPIFFS

Organiza y permite acceder a archivos guardados en una partición de la flash.

Al apagar la placa, los datos permanecen, salvo borrado o corrupción del almacenamiento.

07 · Los comandos de nuestra API

Una dirección, diferentes acciones.

POST/api/dataGuardar una nueva medición
GET/api/dataObtener varias mediciones
GET/api/data/3Consultar el registro con ID 3
DELETE/api/data/3Eliminar el registro con ID 3

09 · Las bibliotecas

Cuatro herramientas, un sistema.

ArduinoJson

Lee y construye mensajes JSON, por ejemplo {"value":24.7}.

esp32_arduino_sqlite3_lib

Integra SQLite para abrir la base de datos y ejecutar sentencias SQL desde el ESP32.

SPIFFS

Permite montar y acceder al espacio de archivos dentro de la memoria flash.

WiFi + WebServer

Conectan la placa a la red y reciben las solicitudes HTTP de la API.

11 · El modelo de datos

¿Qué información guardamos?

CREATE TABLE data ( id INTEGER PRIMARY KEY, device TEXT NOT NULL, sensor TEXT NOT NULL, value REAL NOT NULL, timestamp INTEGER NOT NULL );

Una medición contiene

id — identificador del registro
device — dispositivo de origen
sensor — qué se midió
value — valor medido
timestamp — momento de medición

13 · Demostración real

Desde una notebook, con curl.

1 · Verificar el servidor

curl http://192.168.1.80/api/status

2 · Consultar registros

curl http://192.168.1.80/api/data

3 · Enviar una medición

curl -X POST \ http://192.168.1.80/api/data \ -H "Content-Type: application/json" \ -d '{ "device":"esp32-01", "sensor":"temperature", "value":24.7, "timestamp":1770000000 }'

La dirección 192.168.1.80 es ilustrativa. Usar la IP real que muestra el ESP32 conectado a la misma red.

15 · Lo que debemos cuidar

Gran idea para un prototipo.
No es un servidor ilimitado.

!

Escrituras

La memoria flash tiene una vida útil limitada; escribir continuamente puede desgastarla.

≠

Concurrencia

La librería advierte limitaciones para escrituras SQLite simultáneas desde varias tareas.

🔒

Seguridad

Para usarlo fuera de un laboratorio: autenticar, validar entradas y restringir acceso a la red.

También importa seleccionar un esquema de particiones con espacio para la aplicación y SPIFFS.
